# 逐 API Step Router 重构方案与备案

版本：2026-09-12。状态：研究与实施方案，尚未据此采集数据、训练模型或验证收益。

## 1. 核心决策

目标是：在固定 Agent 框架内，每次模型调用前，根据已有 history 和可观测运行状态，选择一个允许的 `(model, effort)`，在最终任务质量满足容忍度的条件下，降低整条任务的实际成本。

建议将原备案中的“完全抛弃已有 Router Baseline”改为：

> 不把现成 Router checkpoint 或原论文的模型池作为项目启动条件。采用统一模型池、统一 Agent harness，自行实现可复现的路由对照与 Ours。外部 Router 能公平适配则补充；暂时不能适配则说明原因，不阻塞主线。

理由：缺少 checkpoint 会增加复现成本，但不能证明该方法不适用；四档和六模型也不是不可调和的架构限制。没有学习型 Router 对照时，可以证明相对固定模型的收益，尚不能证明优于已有路由方法。

推荐实施顺序：

1. 完成费用审计、任务评估、调用前状态记录和可恢复环境。
2. 固定两模型池，跑齐固定模型、随机混合、规则路由和简单学习型路由。
3. 通过同状态分支实验，监督学习“最终成功收益”和“剩余费用”。
4. 采集 Router 自己访问的状态，迭代更新训练数据。
5. 两模型方案有效后扩展为四模型；只有监督学习方案存在明确瓶颈时再做 RL。

这里“从头设计”指设计 Router 的数据、决策目标和训练流程，默认复用开源预训练编码器，不从零预训练语言模型。

执行模型也不必全部开放权重：只训练 Router 时，可以把候选 API 当作黑盒环境。复现限制来自版本可用性、接口与费用变化，需要通过冻结和日志说明；Router 本身的实现、权重及训练协议则可以独立开放。

## 2. 任务定义与验收目标



### 2.1 路由边界

- 一个 routing step 对应一次逻辑上的模型生成请求。一次生成包含多个工具调用时，这些调用仍属于该次模型决策产生的执行结果。
- 状态 `h_t` 包含调用前可见的 system、messages、工具描述与结果、剩余预算、已用步数、前一模型以及服务端实际可提供的缓存元信息。
- 动作 `a_t` 是注册表内的一个 `(model, effort)` 配置。第一阶段每个模型固定一个 effort，暂不扩大动作空间。
- 转移包括模型生成、工具执行，以及由此产生的新 history 和环境状态。
- 模型执行器保持冻结。Router 不改写用户任务，不额外承担任务规划、答案整合或工具选择。
- API 原始 KV cache 通常不可见，也不假定不同模型共享 KV；只有实测可用的缓存状态可以成为输入。

history 是可观测信息，不一定是完整 Markov 状态。因此实现可以采用带完整可见历史的策略，不必声称恢复了真实环境的全部隐状态。

### 2.2 优化目标

令 `Y` 为最终任务成功或预先确定的质量分数，`C` 为整条任务的运行费用：


\min_\pi J_C(\pi)=\mathbb E_\pi[C]
\quad\text{s.t.}\quad
J_Y(\pi)\ge J_Y(\pi_{\rm ref})-\delta.


`π_ref` 是在验证阶段选定并冻结的最优固定模型策略。它是池内实测参考，不预设某个品牌在所有任务上最强。

建议预注册的目标草案：最终成功率下降容忍度 `δ = 1 个百分点`，期望平均费用下降至少 `30%`。这两项是待验证目标，不是已有结论；小样本 pilot 仅用于估计可行性和样本量，不能据此承诺 1 个百分点的不劣性。

二元成功率和连续 rubric 分数分别报告。如果要汇总不同任务集，必须在评估前固定归一化方法与任务集权重，不能直接把任意评分尺度混合为 accuracy。

### 3.2 划分与冻结协议

1. 先按 task/repository/task family 划分，再运行和拆分轨迹；同一任务的所有 step、分支和重复采样进入同一划分。
2. 训练集采集反事实分支；验证集选超参、预算与路由阈值；最终测试集只用于冻结策略后的评估。
3. 保存 dataset revision、task ID、环境镜像 digest、工具版本、evaluator 版本、模型 ID、endpoint、价格表日期和随机种子。
4. 使用在线网页的任务需冻结可访问材料或明确作为动态环境实验；不同日期的网站变化不能归因于 Router。
5. 新旧 benchmark 之间按任务内容去重。用旧版同一任务训练、新版同一任务测试仍可能泄漏。

当前项目的七类单任务样例继续承担集成冒烟测试。它们不足以训练 Router，也不足以推断跨任务质量与成本收益。

## 4. 模型池、四档映射与单模型 Baseline



### 4.1 推荐从 P2 开始，扩展到 P4

下面给出基于现有候选列表的研究起点。它们不是“当前市场最强/最便宜”的排名，实际可用版本、工具调用兼容性、上下文长度、effort 支持和价格均须在冻结前核验。


| 实验池       | 候选配置                                                                                         | 定位                       |
| --------- | -------------------------------------------------------------------------------------------- | ------------------------ |
| P2：最小可行实验 | `openai/gpt-5`、`openai/gpt-oss-120b`，各固定一种可用 effort                                          | 两动作，先验证替换步骤是否能够省钱并保持终局质量 |
| P4：主实验扩展  | `google/gemini-2.5-flash-lite`、`openai/gpt-oss-120b`、`deepseek/deepseek-v3.2`、`openai/gpt-5` | 增加费用跨度和模型能力互补            |
| P6：可选复现实验 | 用户原列出的 MTRouter 六模型                                                                          | 用于复现与扩展，不作为项目启动条件        |


P2 的两者仅是初始候选。若 pilot 中质量差距或费用差距过小，按事先确定的标准从候选池换一对，再冻结正式实验；不能根据测试集表现选模型。若研究目标改成最新模型池，应在正式采集前统一替换并重新 pilot，建立独立实验版本。

四档可以这样注册：

```yaml
# 设计示意：不是当前 router.toml 可直接加载的完整配置。
# 每项还需补充 provider、实际版本、固定 effort、价格和能力字段。
actions:
  c0: {model: google/gemini-2.5-flash-lite}
  c1: {model: openai/gpt-oss-120b}
  c2: {model: deepseek/deepseek-v3.2}
  c3: {model: openai/gpt-5}
```

这里 `c0–c3` 是配置标识，不宣称模型具有全局单调的能力排序。一个动作唯一对应一个配置；只有 effort 等参数确实不同，才应把同一个模型注册为两个不同动作。

如果四个 tier 与四个配置一一对应，“输出 tier”和“输出模型索引”在动作表达上等价。关键区别在于标签是主观难度，还是执行该动作后的质量与费用，以及网络是否允许共享候选模型特征。建议内部做候选动作评分，外部继续输出 tier/config ID。

### 4.2 如果只跑单模型 Agent，究竟选哪些？

**P2 就跑两个固定模型，P4 就跑四个固定模型。** 每个模型从任务开始执行到结束，使用相同 Agent 框架和工具。不能只跑最强模型：否则无法知道省钱是否只是把工作转移给本来就足够好的便宜模型。

根据验证集选定池内最优固定模型为质量参考；同时保留所有固定模型的质量—费用散点及 Pareto 前沿。若额外加入池外强模型，应单列为系统参考，不纳入“同模型池 Router 改进”的因果比较。

### 4.3 MTRouter 的六模型与 SquillaRouter 的四档如何处理？

- **MTRouter：**六模型是实验配置。其公开代码支持配置模型池并训练 Q-function；可以换成统一 P4 重新训练，明确命名为“统一模型池下重训的 MTRouter”。本次未确认有可直接下载使用的官方 checkpoint，因此不将其作为硬依赖。[MTRouter 使用指南](https://github.com/ZhangYiqun018/MTRouter/blob/main/usage-guide.md)
- **SquillaRouter：**保留四类输出并映射到同一 P4。若使用原 checkpoint，这是迁移基线，必须校准；不能把原有“难度档位”直接视为新模型池的质量标签。
- **Ours：**学习同一 P4 的动作结果；无需假设四个模型按难度形成统一顺序。
- **P2：**Ours 使用两个合法动作。没有必要为了兼容原四类 checkpoint 把两个模型重复填成四档。

所有方案统一是否启用风险升级、失败回退、重试和 fallback；若某个系统需要额外保护规则，应单列“原生配置”与“统一规则配置”，避免把规则收益混为模型学习收益。

简单学习型对照可以采用冻结编码器，加 `history + candidate metadata` 的小型评分头，以采集策略下的终局得分为监督；随后加入显式成本版本。未经逐项核对原实现，不将其命名为“MTRouter 复现”。

不要把“MTRouter 的 cost 仅间接影响”概括为整个项目都不支持显式成本：其默认神经 Q-function 配置与仓库中的显式 score–cost 对照需要分别说明。因此，“增加 cost head”必须与已有成本感知方法比较，不能单独作为区别于 MTRouter 的充分理由。[MTRouter 官方代码](https://github.com/ZhangYiqun018/MTRouter)

比较分两层进行：一层固定训练数据、编码器、训练预算，只改变标签与决策方法；另一层固定总采集预算，比较随机轨迹采集和分支采集的端到端收益。Ours 使用更多完整 rollout 时，必须报告这部分开销。

## 6. SFT 数据：从“这一步像不像”改成“执行后会怎样”



### 6.1 一条训练记录至少包括什么？

```text
task_id, task_family, split, episode_id, step_id
history_before_call, allowed_actions, budget_remaining, previous_action
environment_snapshot_id, history_hash, environment_version
action_id, model_version, effort, behavior_policy_id, continuation_policy_id
sampling_probability, rollout_seed
terminal_success_or_score
current_step_cost, remaining_episode_cost, latency, token_usage_breakdown
termination_reason, evaluator_version, price_version
```

环境快照和最终评分属于采集/监督侧数据，不是推理时提供给 Router 的隐藏答案。特征仅来自调用前可观测的信息；未来生成长度、候选模型本步输出、终局 evaluator 结果不能进入 Router 输入。

历史序列化和截断规则固定并版本化。优先保留原任务、近期完整工具交互与预算信息，避免截断半个工具调用；若使用摘要，所有方法共享摘要过程，并计入生成摘要的运行费用。

### 6.2 分支采集流程

1. 在训练任务上运行固定强参考策略，保存每次调用前的 history 与可恢复环境。
2. 按任务阶段、工具类型、历史长度、失败恢复阶段分层抽样 step，同时保留随机抽样，防止只收集容易替换的步骤。
3. 从同一个调用前状态恢复多个分支，对每个候选动作生成一步并实际执行工具。
4. 冷启动时，随后统一由强参考策略继续到任务结束。
5. 每个 `(state, action)` 独立重复若干次，记录最终结果和从当前步起的全部费用。
6. 强模型动作也进行对应分支实验；不要把原 trace 的一次成功当作该状态的强模型成功概率为 1。

“同一个状态”要求 history 和环境状态一致。代码任务至少要恢复文件、工作目录和必要进程状态；AppWorld 需要考虑数据库与交互解释器状态。只替换 trace 里的文本，不执行其工具副作用，不构成有效反事实实验。

若只能从任务开始确定性回放，应先验证回放后的状态哈希与关键观测一致。不能可靠恢复的环境，先采用完整混合轨迹采集，不产生声称为同状态对照的标签。

### 6.3 标签的准确含义

对于后续策略 `ρ`：


Q_Y^\rho(h_t,a)=\mathbb E[Y\mid h_t,a_t=a,\text{后续使用 }\rho],
\qquad
Q_C^\rho(h_t,a)=\mathbb E[\sum_{u=t}^{T}c_u\mid h_t,a_t=a,\rho].


例如，同一状态下弱模型替换后 4 次续跑成功 3 次，成功率软标签为 `3/4`，同时保留样本数 4。单次成功/失败可以作为一次监督观测，但不足以稳定估计成功概率。

冷启动阶段学到的是 `Q^strong`：强模型负责后续补救时，当前动作的结果。它不等于最优价值，也不等于连续使用当前 Router 时的价值。

质量标签不是“一步 accuracy”；费用标签也不只是该模型这次的报价。便宜模型若引入多轮修复，剩余费用可能更高。此前已发生的费用是沉没成本，不放进本步 cost-to-go 标签，但剩余预算应作为输入。

单步输出相似性只作为辅助分析或低成本筛选信号。工具参数、代码补丁、合法的不同解法未必在文本上相似；相似也不保证最终成功。即使筛选，也应随机复核一部分被筛除样本。

## 7. Ours 的监督训练与部署决策



### 7.1 默认结构：共享编码器与双预测头

```text
调用前 history + 可观测运行特征
                   ↓
              冻结编码器
                   ↓
与候选配置特征组合 → success head → Q_Y(h, a)
                   → cost head    → Q_C(h, a)
                   ↓
       校准后的决策规则 → config_id
```

候选配置特征包含模型标识、固定 effort、可用工具/模态/上下文能力以及价格信息。初版训练小型预测头即可；数据规模与误差分析支持后再考虑编码器 LoRA。新模型加入仍需采样与校准，不能宣称只填写 metadata 就能可靠零样本路由。

### 7.2 怎么用 `(history, accuracy, cost)` 做 SFT？

对二元最终成功，使用 BCE；对非二元 rubric，使用符合该评分含义的回归损失。费用可做统一尺度归一化后用 Huber：


\mathcal L_Q=\operatorname{BCE}(\widehat Q_Y,y)
+\alpha\operatorname{Huber}(\widehat Q_C/C_{scale},c/C_{scale}).


`C_scale` 在训练集上固定，推理时费用还原到统一货币单位。重复样本按采集设计处理，避免一条超长任务或高重复状态主导训练；评估按独立任务聚合。`α` 只平衡预测损失，不直接表示用户愿意牺牲多少质量。

部署时，先屏蔽工具、模态、上下文或预算不兼容的动作，再用下列一种决策方式：

- 质量容忍规则：在 `Q_Y(h,a) ≥ Q_Y(h,a_ref) − ε` 的动作中，选择预测剩余费用最低者。
- 效用规则：选择 `argmax_a [Q_Y(h,a) − λ Q_C(h,a)/C_scale]`，在验证集扫描 `λ`。

`ε` 是局部决策参数，`δ` 是整个任务分布的质量容忍度，两者不相等；局部每步看似安全的替换，累计后仍可能显著降低成功率。最终依据完整 rollout 选择满足全局质量目标的配置。

预测不确定或输入超出训练覆盖时，使用经过校准的保守回退策略，并记录回退率。回退有助于控制风险，本身不构成“不掉点”的保证。

### 7.3 如果一定要训练“直接输出档位”的 Router

可以先按以上规则生成目标动作，再训练分类器：


a^*(h)=\arg\max_a[\widehat Q_Y(h,a)-\lambda\widehat Q_C(h,a)/C_{scale}],
\qquad
\mathcal L_{actor}=-\log\pi_\theta(a^*(h)\mid h).


动作标签优先基于有覆盖的分支结果或交叉验证得到的预测；不把训练集上的过拟合高分当成可靠标签。需要平滑标签时，可对相同效用做带温度的 softmax，但它是决策蒸馏分布，不是成功概率。

第一版建议直接使用双头打分器决策，减少一个蒸馏阶段。只有 Router 延迟或部署形态需要时，再蒸馏成四类分类器。

“只学 accuracy 就必然选择最强模型”并非严格成立，因为不同模型可能互补；但质量目标本身不表达节省费用的偏好。显式费用目标和全局质量约束才是本方案成本控制的来源。

## 8. 数据聚合：处理连续路由的分布偏移

第一版监督 Router 在训练任务上实际运行，采集它自己访问的状态，再重复分支标注与训练：

1. 用当前 Router 或它与参考策略的预定义混合策略 roll-in。
2. 在新访问状态探索候选动作。
3. 分别进行强参考 continuation 的诊断实验，以及当前 Router continuation 的部署匹配实验。
4. 记录 continuation 版本；部署匹配预测头使用对应版本数据，必要时重跑旧状态。
5. 更新 Router 后，再在独立验证任务上跑完整轨迹。

不能把不同 continuation 下的终局标签无标识地混为同一个 Q 函数目标。早期强 continuation 数据可以作为冷启动或辅助监督；如长期保留，需要显式条件化、重新标注或采用有依据的离线学习方法。

本阶段借鉴 AggreVaTe 的状态分布覆盖与后续损失监督思想，但改成当前策略 continuation 后，不直接沿用原算法的理论保证。相关思想已有研究基础，不能把“强轨迹单步替换”本身作为独有创新。[AggreVaTe 原论文](https://arxiv.org/abs/1406.5979)

## 9. RL：作为第二阶段增强，而非启动依赖



### 9.1 启动条件

同时满足以下条件再开展 RL：监督 Router 已在验证集显示可重复收益；环境 reset/计费/evaluator 可靠；存在足够 rollout 预算；误差分析显示主要瓶颈来自连续决策，而非数据或接口错误。

### 9.2 推荐实现

- 执行模型冻结；Router 是小型 categorical actor，动作仅为合法的 `(model, effort)`。
- 从监督策略初始化，采用 PPO 或同类成熟策略梯度实现；价值网络分别预测后续质量和后续费用。
- 设归一化费用 `c'_t=c_t/C_scale`，有限任务采用不折扣回报或明确其折扣含义。
- 每步奖励 `−c'_t`；终局额外奖励 `ηY`。预算耗尽、超时和错误终止按预定规则计入结果。
- 拉格朗日乘子根据训练/约束估计更新：


\eta_{k+1}=\max0,\eta_k+\beta[Y_{target}-\widehat J_Y(\pi_k)],
\quad Y_{target}=J_Y(\pi_{ref})-\delta.


质量不达标时增加 `η`，提高成功收益的相对权重。真正的策略选择仍以独立验证集的完整结果为依据；有限数据、优化误差和分布变化下，该更新不提供自动满足质量约束的保证。

策略梯度只需要 Router 选动作的 log-probability，不需要获得外部执行模型的梯度。PPO 的梯度以 Router 动作为单位；这里不训练执行模型输出的所有 token。

任务预算是显式状态与终止条件。若剩余预算无法承担参考模型，按预定义预算规则处理并如实报告约束不可行情况，不能假装 fallback 总能保证质量。

### 9.3 为什么不优先 AlphaZero/MCTS？

持廉价精确恢复。先把搜模型调用与工具执行昂贵且随机，环境也不一定支索预算花在离线分支采集上，再训练低开销策略更容易落地。若后续能证明离线树搜索有收益，再单列研究，不将在线 MCTS 作为部署依赖。

Router-R1 和 ToolOrchestra 可提供 RL 工程参考，但原版同时学习更广的生成/编排行为。限制为纯路由后应命名为改编版本，并重新验证。[Router-R1](https://github.com/ulab-uiuc/Router-R1)、[ToolOrchestra](https://github.com/NVlabs/ToolOrchestra)

## 10. 费用、评估与统计口径



### 10.1 费用必须覆盖实际执行

运行费用记录：Router 推理、执行模型输入/输出、缓存读写、收费工具、已发生的收费失败与重试，以及额外摘要/验证调用。按供应商定义解释字段，避免把已包含在 output tokens 的 reasoning tokens 再重复计费。

分别报告：任务运行费用、离线评测费用、训练及数据采集费用。运行中实际使用的 verifier 算运行费用；仅用于离线打分的 evaluator 单列。计费无法精确获知时注明估算方法，保留原始 usage，不能将未知费用记为零。

同模型切换、跨模型切换和前缀缓存会改变实际成本与延迟。所有方法使用一致缓存策略；分支实验的先后顺序可能人为预热缓存，需要隔离或控制。优先同时保留实际账单口径和固定价格表重算口径。

用户原表中各模型的美元数值不作为本项目单位 token 价格。模型费用排名必须由当前冻结价格和本项目实际输入/输出量计算。

### 10.2 公平比较条件

固定任务集、Agent prompt、工具、合法动作、effort、上下文处理、输出上限、最大步数、总预算、重试及 fallback 规则。提供商请求格式可以做必要适配，但必须版本化并在对应所有方法中一致使用。

优先使用官方程序化 evaluator；需要 LLM judge 时，固定独立 judge、prompt、版本和采样设置。不能让被评测 Router 决定用哪个模型给自己评分。

各策略在同一批任务上配对评估，执行顺序交错以缓和 API 时间漂移。未提供种子能力的 API 要记录此限制，多次运行用于估计随机性；不能声称不同模型共享种子就共享相同随机过程。

### 10.3 主表与质量验收

主表至少包含：任务成功率/质量分数、相对参考质量差、平均费用、节省比例、延迟 P50/P95、调用次数、回退率与预算/超时终止率。费用统计包括失败任务，不仅统计成功样本；“每个成功任务的费用”只能作为补充指标。

绘制完整的质量—费用 Pareto 曲线，并与固定模型、随机混合、规则路由比较。根据验证集选择一个工作点，再在测试集确认；不要用测试集扫描出的最佳点作为最终部署结果。

正式“不劣于参考”验收采用配对任务层面的单侧置信区间，例如：


\operatorname{LCB}*{95}(J_Y(\pi)-J_Y(\pi*{ref}))>-\delta.


按独立任务或任务家族进行聚类抽样/置信区间计算；同一任务的多次 rollout 不能全部当成独立任务。既报告总体，也报告预注册任务组的汇总表现，避免平均值掩盖某类任务明显退化。

样本量须通过 pilot 估算。仅作数量级示例：二元结果、独立配对任务、真实质量差约为 0、两策略结果不一致比例约 `q=0.1` 时，正态近似下单侧 5% 显著性、80% 功效、`δ=0.01` 约需 `(1.645+0.842)^2 q/δ^2 ≈ 6,200` 个独立任务。实际需考虑方差、聚类和数据集规模；几十到几百个任务通常只能提供探索性证据。

## 11. 实施阶段、预算与退出条件


| 阶段           | 主要工作                                      | 完成标准               | 不满足时                   |
| ------------ | ----------------------------------------- | ------------------ | ---------------------- |
| G0：测量基础      | 补齐计费、固定 evaluator、action registry、恢复/回放验证 | 同状态分支可比较，费用可审计     | 缩小到可恢复环境；保留全轨迹学习对照     |
| G1：模型 pilot  | 运行 P2/P4 固定模型和随机/规则对照                     | 有质量与费用差距，且存在潜在替换空间 | 调整候选池一次并冻结；若仍无空间，报告负结果 |
| G2：监督 Router | 分支采集，训练双头，验证校准与完整 rollout                 | 达到预设质量目标且优于简单对照    | 增强状态覆盖、改进费用/标签；保留规则方案  |
| G3：数据聚合      | 当前策略 roll-in 与匹配 continuation             | 混合轨迹收益稳定，误差随迭代下降   | 停留在可验证的保守策略，不扩模型池      |
| G4：四模型扩展     | 同池比较，补 MTRouter 重训等外部对照                   | 比 P2 有可重复增益        | 以 P2 作为主交付             |
| G5：可选 RL     | SFT 初始化，受约束策略优化                           | 同质量条件下继续降低实际费用     | 不采用 RL，交付已验证监督 Router  |


建议首轮规模仅用于估算预算：从可开发任务中选约 40 个任务，P4 每模型跑 2 次，共 320 条完整轨迹；先选 60 个状态做 P2 分支，每动作 4 次，共 480 条后缀 rollout。任务不足时不通过复制任务虚增独立样本量。实际启动规模根据一次完整任务和一次后缀的实测费用缩减。

采集预算估算：


B_{collect}\approx N_{task}KS\bar C_{episode}
+N_{state}AR\bar C_{suffix}
+B_{aggregation}+B_{judge}+B_{compute}.


`K` 为固定模型数，`S` 为重复次数，`A` 为每状态探索动作数，`R` 为分支重复数。先记录实测均值和长尾，再确定 `B_collect`、`B_RL` 上限；没有费用数据时不承诺具体美元预算。

主预算优先保证 G0–G3；外部完整系统复现和 RL 都有独立预算上限。还应计算采集/训练的摊销：额外训练成本除以每个部署任务的实测节省，得到大致回本任务量。

## 12. 可直接采用的备案



### 备案 A：无外部 checkpoint 的主线

**触发条件：**现有 Router 的权重不可得、接口适配超过预设工程预算，或完整系统改变了需要控制的 Agent 行为。

**执行方案：**

1. 统一两模型池和 Agent harness，固定模型参数与费用口径。
2. 跑两个固定模型、随机混合、规则升级、任务级路由、简单学习型评分器。
3. 用强参考轨迹与同状态动作分支，训练最终质量/剩余费用双头 Router。
4. 用 Router 实际访问状态迭代采集，控制强 continuation 到混合 continuation 的分布偏移。
5. 在满足预注册质量容忍度的工作点比较费用，再决定是否扩展四模型。
6. 开源可发布的 Router 实现、模型权重、动作注册表、采集协议与评估脚本；数据按来源许可发布或提供重建索引。

**研究定位：**证明在统一执行框架与固定模型池下，history 驱动的逐步路由相对固定模型、随机与简单学习型路由的价值。未复现的外部方法只作相关工作，不声称超过它们。

### 备案 B：中途环境不可可靠恢复

保留完整混合策略轨迹采集，记录每次动作及其采样概率，用终局结果和实际 return-to-go 监督已执行动作。通过不同混合策略增加覆盖，先不使用无法验证的反事实标签。

这类数据只提供行为策略下已执行动作的反馈；不能给所有未执行模型填同一个终局标签，也不能默认得到无偏的任意策略价值。若要离线改进，应处理覆盖与策略分布差异。与此同时把分支方法限制到可验证恢复的任务子集。

### 备案 C：RL 不稳定或收益不足

交付监督双头 Router + 验证集选择的保守阈值 + 回退规则。RL 作为后续研究，不影响已完成系统交付。若学习型 Router 没有超过简单规则，交付成本—质量测量与规则方案，并明确报告未获得学习收益。

## 14. 最小消融与最终交付

最小消融包括：任务级 vs 逐步路由；仅质量 vs 质量+剩余费用；当前步费用 vs 剩余费用；强策略状态 vs 聚合状态；强 continuation vs 部署匹配 continuation；无预算状态 vs 有预算状态。若篇幅与预算有限，优先前四项。

现阶段不把“双头预测”“成本奖励”“强轨迹单步替换”单独宣称为创新。这些与已有价值预测、模仿学习和路由研究存在重叠。潜在贡献需要通过实验建立，例如：特定任务分布上更可靠的替换标签、可审计实际费用下的控制方法，以及连续路由的状态覆盖带来的稳定增益。

最终交付物：冻结实验 manifest；费用与状态采集协议；可重建的训练数据索引；Router 权重及推理入口；全部必做对照的运行配置；质量—费用曲线及置信区间；训练费用和部署摊销分析；包含失败与负结果的实验报告。
